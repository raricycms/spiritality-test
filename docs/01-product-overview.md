# 01 产品概述

## 1.1 项目定位

**灵性测试**是一款单页 Web 应用（Single-Page Application, SPA），让用户进行一次看似"不可能"的"透视"测试：在每一轮中，HTML 页面上会出现一个 1–5 的数字，但用户看不见——因为这个数字被一个不透明的组件盖住了；用户要去猜这个数字是什么。每场测试 30 轮。

应用不评判"灵性是否存在"，而是基于用户自己的全部历史答题数据，用贝叶斯方法给出一个概率估计：**在用户的数据下，"真实命中率"不等于 20% 的后验概率有多大**。

> 20% 是纯随机猜测 5 选 1 的命中率，作为零假设 `H₀: p = 0.20`。
>
> 概率采用 **Savage-Dickey 密度比** 计算（`BF_{01}` 是支持 `H₀` 的证据强度，`P(灵性起效) = 1/(1 + BF_{01})`）。这个方法在样本量极大、频率只是微微偏离 20% 时仍能给出"灵性有影响"的正确判断。详见 `06-statistics.md`。

> 20% 是纯随机猜测 5 选 1 的命中率，作为基准线。

## 1.2 用户故事

- 作为用户，我希望能开始一场 30 轮的测试，并在每轮看到一个被遮挡的数字。
- 作为用户，我希望能用 **5 个按钮** 或 **键盘数字键 1–5** 作出猜测，并按 Enter 提交。
- 作为用户，我希望在每轮提交后立刻看到反馈：是否猜对、正确答案是几。
- 作为用户，我希望在 30 轮结束后看到本场正确率和详细答题记录。
- 作为用户，我希望看到基于我所有历史数据的 **"灵性起效概率"**。
- 作为用户，我希望能查看历史的所有 session，并可以导入/导出/清空。

## 1.3 关键术语

| 术语 | 含义 |
|---|---|
| **target** | 本轮的目标数字，取自 `{1, 2, 3, 4, 5}`，在本轮被遮挡，对用户不可见 |
| **guess** | 用户对 target 的猜测 |
| **round** | 一轮：从 target 就绪到揭示反馈的全过程 |
| **session** | 一次完整的测试，连续多轮（默认 30 轮） |
| **trial** | 一道题；即一次"猜测并揭示"的 round（状态为 `REVEALED`） |
| **k** | 累计正确次数 |
| **n** | 累计答题次数（即 trial 总数） |
| **accuracy** | `k / n`，朴素正确率 |
| **spiritualityEffectiveProb** | 基于 Savage-Dickey 密度比，在 1:1 零/备假设先验比下的 `P(H₁: p ≠ 0.20 \| data)` |

## 1.4 非目标（明确不做）

- **没有账号系统、没有云同步**。所有数据本地化。
- **不判定"灵性存在 / 不存在"**。我们只做概率估计，不下结论。
- **不展示诱导性文案**（如"你真有灵性！"），所有表述保持中性统计化。
- **不做推送、广告、追踪、分析**。

## 1.5 核心 UX 原则

1. **透明**：所有概率与算法对用户可见，用户可以查看使用的 Beta 先验、空值点、视图切换（点零 / 单边 / 可信区间）。
2. **可重置**：用户可以一键清空全部数据。
3. **公平感**：每一次测试的"目标数是先于我猜测就存在的"，这一点必须在 UX 上可感知，并且必须由架构强制（详见 `03-core-mechanics.md`）。
4. **简朴**：UI 风格贴近 macOS Sonoma，圆角、半透明、轻拟物，去除装饰性元素。

## 1.6 用户文案建议

- 主标题："灵性测试"
- 测试说明：在 Reveal 后短提示——"答案已经存在；你的猜测不影响目标数。"
- 灵性概率标题："灵性起效的概率"（注：不是"灵性指数"）。
- 概率下方的副标题（默认视图）：`P(p ≠ 0.20 | 你 N 次答题)`，并附"如何计算？→" 链接到 `06-statistics.md` 的解释。
- 提供视图切换：默认 `p ≠ 0.20`（点零 / Savage-Dickey）、备选 `p > 0.20`（单边）、`p` 95% 可信区间三种。
